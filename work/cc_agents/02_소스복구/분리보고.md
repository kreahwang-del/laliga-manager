## □ 빌드 방법
| 명령 | 결과 |
|---|---|
| `python src/build.py` | `src/dist/cur.html` (개발값) |
| `python src/build.py --deploy --appv 247` | `src/dist/index.html` (배포값). `--appv` 없으면 중단 |
| `-o 경로` / `--check 비교파일` | 출력 경로 지정 / 바이트 비교·sha256 출력(다르면 첫 차이 위치 표시 후 종료 코드 1) |

- ㅇ 치환 규칙(모두 원본에 없던 표식이라 충돌 없음 — 분리 전 0건 확인)
  - `__DATA__("이름")` → `data/이름.json`에서 줄바꿈(`\n`·`\r`)만 지운 원문
  - `__CFG__("키")` → `build_config.json` 값. 현재 `APPV`(원본 `const APPV=245;`), `LGMKT_OFF`(원본 `var LGMKT_OFF=true;`)
  - `__ENGINE_SRC__` → 엔진 본문의 `json.dumps(…, ensure_ascii=False)`
  - `@@ASSET:text|b64|dataurl:…@@` → 자산 파일(텍스트 그대로 / base64 / data URL)
- ㅇ 모든 텍스트 입력에서 `\r`을 지움(원본은 LF 전용) → Windows `autocrlf`로 CRLF가 되어도 결과 같음(CRLF 변환 사본으로 빌드해 바이트 동일 확인)
- ㅇ 데이터 JSON 형식: 원문 그대로 두고 **최상위 요소 사이에만 줄바꿈**을 넣음(선수 1명 = 1줄). 아무 JSON 도구로나 읽힘
  - 3단계(data-rights)에서 다시 쓸 때: 들여쓰기 있는 JSON으로 저장해도 동작은 같지만 공백만큼 커짐 → 한 줄 1행 형식 권장
  - 원본 일부(TOCAL·STAD·mgrs 등)는 `", "` 형식이라 줄 앞에 공백 한 칸이 남음(원문 보존 때문)

## □ 발견 사항
1. **워커 경기에 AI 팀 호흡(chem)이 빠짐** (버그 성격, 수정 안 함)
   - AI 팀 호흡은 `runMatch` 래퍼(`app/0500_v156_chemistry.js` 68줄)에서만 계산 → 워커 경로 `simAsync`에는 없음
   - E4 패스 성공률 보정 `chemK=.15`가 워커 경기(우리 경기일의 다른 경기, 모든 리그 엔진)에서만 빠짐. 워커 실패 시 대체 경로에서는 다시 적용됨
   - `msim.js`(EA_OFF, 빠른 결과)에는 영향 없음
   - 고치려면 `simAsync`도 같은 방식으로 감싸면 됨 → 경기 결과가 바뀌므로 사용자 승인 필요
2. 워커 경기는 `Math.random` 시드를 고정할 수 없어 재현 불가(설계상). 검증할 때는 `matchhash.js`처럼 `opt.rnd`를 넘겨야 함
3. 코드 안에 남은 권리 관련 상수(3단계 data-rights 이관 후보, `src/data/`로 아직 안 뺌)
