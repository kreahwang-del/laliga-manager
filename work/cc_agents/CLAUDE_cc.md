## □ 병합 규칙
- ㅇ 각 에이전트는 작업 브랜치(`agent/<에이전트>-<주제>`)에서만 작업
- ㅇ 병합 전 순서: 작업자 자체 검증 → `code-review` → `playtest` 회귀 → 총괄 병합
- ㅇ `code-review`·`playtest`의 「필수」 지적이 남아 있으면 병합하지 않음

## □ 공통 규칙
- ㅇ 사용자에게는 존댓말을 쓰고 반말은 쓰지 않음. 개조식은 괜찮음. 간결하게 쓰고 근거·출처를 밝힘
- ㅇ 방향 선택이 필요하면 먼저 사용자에게 물음. Word·Excel·PPT 등 별도 파일은 만들기 전에 물음
- ㅇ 커밋·push는 사용자가 요청할 때만 함. `main` 배포는 사용자 확인 후에만 함
  - `main`에 push하면 설치된 앱이 `version.json`을 보고 자동 업데이트됨 → 특히 주의
- ㅇ 소스 복구 전에는 엔진을 고칠 때 엔진 본문(E3/E4)과 `ENGINE_SRC`를 함께 고침
  - 문자열 치환으로 고칠 때마다 `assert s.count(anchor)==1`로 확인
- ㅇ 모든 변경은 전후 검증 결과(시뮬 수치, 스크린샷, 오류 로그)를 `work/99_검증로그/`에 남김
- ㅇ 같은 파일을 두 에이전트가 동시에 고치지 않음 → 총괄이 파일별 담당을 정해 줌
- ㅇ 시뮬처럼 오래 걸리는 작업은 백그라운드로 돌림(10시즌에 약 2시간)
- ㅇ 접근이 막힌 사이트(트랜스퍼마르크트, 나무위키 등)는 우회하지 않음. CAPTCHA는 처리하지 않음. 다운로드는 사용자의 명시적 허락을 받음. 제3자 자산은 라이선스를 먼저 확인함
