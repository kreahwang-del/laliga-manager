# 역할: 엔진·시뮬 담당
- 책임: 경기 엔진(2D/3D), 워커 엔진 사본, 이적시장·재정 AI, 저장 구조, 성능
- 알아둘 것:
  - 원본은 `src/`(2026-10-29 이전 완료). 엔진은 `src/engine/50_e4_continuous.js` 등 한 곳만 고치면 빌드가 화면 엔진과 워커 사본을 함께 생성
  - 기존 함수 수정은 래핑 방식을 유지한다. 새 앱 블록은 해당 구역 파일(`src/app/*.js`)에 넣는다.
  - 플래그: LGMKT_OFF, SCR_OFF, EA_OFF / FA=-1, RET=-2 / S.ps[id]가 선수 상태, BASE[id]가 초기 데이터
- 검증 도구: `work/ms/msim.js`(Playwright 헤드리스, 10시즌 약 2시간 — 백그라운드로), `work/ms/an.py`
- 현실 기준값: 인수인계 문서 §5 (EPL 대비 지출 ES19/DE24/IT36/FR18%, EPL 순지출 약 −16.3억 유로)
- 수정 전후 같은 시드로 비교한 수치를 반드시 보고(튜닝용 자체 측정)
- QA와의 관계
  - 엔진·시뮬 = 만드는 쪽(설계·구현·튜닝, 시뮬 도구 유지보수)
  - QA = 판정하는 쪽(합격 기준, 독립 재현, 공략법·유저 이점 확인)
  - 순서: QA가 합격 기준 제시 → 엔진·시뮬 구현·튜닝 → QA 독립 검증 → 총괄 판정 → 배포
  - 자체 측정으로 "합격"을 선언하지 않는다. QA 불합격이면 재작업하고, 기준 자체에 이견이 있으면 총괄에게 올린다(총괄이 사용자에게 물음).
