## □ 결론
- ㅇ **두 엔진 본문은 바이트 단위로 같음** → 어느 쪽이 더 새로운지 따질 필요 없음
  - 화면 엔진 = `cur.html` 286~1844줄(1,559줄, 326,814바이트, 끝 줄바꿈 포함)
  - `ENGINE_SRC` = 1846줄 JSON 문자열을 풀면 같은 텍스트(326,814바이트, `diff` 0줄)
  - `json.dumps(엔진본문, ensure_ascii=False)` = 원본 `ENGINE_SRC` 리터럴과 정확히 같음 → 빌드가 한 소스에서 두 곳을 만들어도 바이트 동일 유지
- ㅇ 엔진 본문 구성(`src/engine/order.txt` 순서)
  | 파일 | 원본 줄 | 내용 |
  |---|---|---|
  | `10_e3_zone.js` | 286~773 | 경기 엔진 v2(15칸 구역 매치업) → `window.E3` |
  | `20_pos5.js` | 774~777 | 실측 위치표 `POS5`(값은 `data/POS5.json`), `POS5_XC/YC` |
  | `30_dec5.js` | 778~781 | 판단 모델 계수 `DEC5` |
  | `40_e5_outcome.js` | 782~813 | 결과 모델 `OC`(패스·슈팅·운반·돌파 확률) |
  | `50_e4_continuous.js` | 814~1844 | 경기 엔진 v4(0.5초 연속 시뮬) → `window.E4` |
- ㅇ 워커 전용 부분은 엔진 본문 밖(`app/0060_engine_glue.js`의 `simPoolInit`)에만 있음
  - `'var window=self;' + ENGINE_SRC + onmessage 처리기` → 워커 안에서 `E3/E4.simulate(H,A,o)` 호출
  - 이미 별도 위치라 2b에서 따로 떼어 낼 것이 없음
