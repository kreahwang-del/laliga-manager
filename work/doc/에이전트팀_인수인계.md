## 2. 코드 구조 · 작업 방법(필수)
- **원본은 빌드된 단일 HTML뿐**
  - 예전 원본 블록(`blk_*.js`, `engine5.js`, `build.py`, `design.md`)은 서버 초기화로 사라짐.
  - `cur.html`을 Python 문자열 치환으로 고침. 고칠 때마다 `assert s.count(anchor)==1`로 확인.
  - 상용화 작업을 시작하면 **모듈 분리(소스 트리 + 빌드 스크립트) 복구를 1순위**로 권장.
- **새 코드 블록:** `{const _rdE=render;render=function()`가 있는 줄 바로 다음에 넣음.
- **기존 함수 수정:** 기존 함수를 감싸는 방식으로 고침.
  - 예: `{const _x=fn;fn=function(){const r=_x.apply(this,arguments);…;return r}}`
- **엔진 수정은 두 곳을 함께 고칠 것**
  - 화면에서 도는 엔진 본문(E3/E4).
  - `const ENGINE_SRC="..."`: 워커용 JSON 문자열. 다른 리그 경기를 백그라운드에서 계산하는 데 씀(최대 6개 워커).
- **데이터 위치:** `G.players`(배열 행), `G.clubs`, `G.leagues` 등이 HTML 안 JSON에 있음.
  - 선수 행 형식: `[id, name, club, g, sub, dob, nat, foot, h, ovr, pa, attrs[14], val, hi, cEnd, wage, clause, inj, pro, gt, est, tend, attSh, pos2, …, img]`.
  - `est=2`는 추정 선수. 선수 화면 이름 옆에 "(추정)"이 표시됨.
- **기능 플래그:** `LGMKT_OFF`(이적시장 조정), `SCR_OFF`(재정 규정), `EA_OFF`(모든 리그 엔진). 판정 함수는 `MKON()`, `SCRON()`.
- **특수 구단 값:** `FA=-1`(자유계약), `RET=-2`(은퇴/숨김).
- **저장 데이터:** `S.ps[id]`가 선수별 변경 상태(club, loanFrom 등)를 담음. `BASE[id]`는 초기 데이터.
- **새 게임 / 기존 저장 구분:** `startGame()`과 `devLoad()`를 감싼 부분에서 처리.

## 5. 시뮬레이션 도구 · 현실 기준값
- **실행**
  - 명령: `HTML=... node ms/msim.js 10 out.jsonl "LGMKT_OFF=false;EA_OFF=true"`
  - 반드시 백그라운드 작업으로 실행할 것. `&`로 띄우면 응답이 끝날 때 함께 죽음.
  - 10시즌에 약 2시간 걸림.
- **분석:** `python3 ms/an.py out.jsonl`
  - 출력: 리그별 이적 총액·순지출·건수, FA80, 20명 미만 구단 수, SCR, 한도 초과 구단 수, 연봉 총액, 상위 16명 평균.
- **현실 기준(2025/26)**
  - EPL 대비 이적 지출 비율: 라리가 19%, 분데스 24%, 세리에 36%, 리그1 18%.
  - EPL 순지출: 약 −16.3억 유로.
  - 출처: Football Finance Lab, Deloitte Money League 2026, Deloitte Annual Review, UEFA, Capology.
- **차수별 결과(EPL 대비 비율, 라리가/분데스/세리에/리그1)**
  - 5차: 24 / 38 / 28 / 20%. 현실에 가장 가까움.
  - 6차: 37 / 40 / 48 / 36%. 유럽대항전 수입 2배 탓으로 추정.
  - **7차: 28 / 29 / 38 / 24%.** 현실과의 차이 합계가 5차 29%p에서 22%p로 줄어 가장 가까움.
- **7차 상세**
  - EPL 순지출: +7.4. 현실(+16.3)과 5차(+10.5)보다 낮음 → EPL 지출이 아직 부족함.
  - 20명 미만 구단: 0개. 승점 감점: 10시즌 동안 3건.
  - 시즌 말 SCR 평균이 계속 올라감 → 다음 조정 후보.
    - 세리에 0.71→0.95, 라리가 0.64→0.86, 챔피언십 0.61→0.88.
  - 튀르키예 연봉 총액: 1.7배(6차는 2.3배였음).
- **알려진 문제: 저장 데이터 증가(장기 플레이 위험)**
  - 6차 시뮬이 10시즌째에 CPU 0%로 멈춤. 7차는 10시즌을 정상 완료함.
  - 7차 기록을 보면 저장 데이터(`JSON.stringify(S)`)가 시작 시 12.8MB에서 시즌마다 약 1.3MB씩 늘어 10시즌째 26.1MB가 됨.
  - 무엇이 쌓이는지(기록·뉴스·경기 로그·선수 상태 등) 찾아서 오래된 항목을 요약하거나 정리해야 함. 상용 출시 전 필수.

## 7. 상용화 저작권·권리 체크리스트(에이전트팀 최우선)
- **실명:** 선수 이름, 구단 이름·약칭, 감독 이름, 리그명·대회명(챔피언스리그 등)을 모두 가명으로 바꿈.
  - 선수 초상·성명권, FIFPro 집단 라이선스 문제가 있음.
  - 리그명은 국가명으로 씀.
- **이미지:** 선수 사진을 트랜스퍼마르크트 CDN(`tmssl.akamaized.net`, `img.a.transfermarkt.technology`)에서 불러오고 있음 → 완전히 제거.
- **구단 정체성:** 구단 엠블럼과 색 조합(`COLORS`)은 실제 구단을 연상시키지 않게 바꿈.
- **데이터베이스 권리:** 실제 능력치·이적료를 그대로 옮긴 데이터는 EU 데이터베이스권·약관 문제가 생길 수 있음.
  - 가명화와 함께 수치를 재생성하고 분포만 유지함.
  - 위키백과 내용은 CC BY-SA지만, 사실 자체는 보호 대상이 아님.
- **재정 수치:** Deloitte 등 실제 구단 매출 수치(`revSrc` 표기 포함)는 가상 구단 기준으로 다시 만듦.
- **3D 자산**
  - Mixamo 캐릭터·동작: Adobe 약관상 게임 안에서는 사용 가능하지만 원본 파일 단독 재배포는 금지. 상용 출시 전에 약관을 다시 확인할 것.
  - Sketchfab 모델과 실존 인물 얼굴 모델은 사용하지 않음(이미 제외함).
- **라이브러리·폰트:** three.js(MIT), Google Fonts(OFL)는 상용 사용 가능. 다만 고지문을 넣을 것.

## 8. 남은 과제(우선순위 순)
1. **v247 배포 여부 결정:** 선수 데이터와 7차 이적시장을 함께 배포하는 쪽을 권장함(7차가 가장 현실에 가까움). 사용자 확인 후 진행.
2. **저장 데이터 증가 원인 규명·정리:** 시즌당 약 1.3MB씩 늘어남(§5).
   - 같이 볼 후속 과제: EPL 지출 부족, 세리에·라리가·챔피언십 SCR 상승.
3. **소스 모듈화 복구:** 단일 HTML에서 소스 트리와 빌드 스크립트로 분리.
4. **가명화 파이프라인**
   - 이름 생성기(국가별 NAMES가 이미 유망주용으로 있음).
   - 구단·리그 이름 변환표.
   - 능력치 재생성.
