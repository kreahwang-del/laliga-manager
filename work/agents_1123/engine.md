- 로딩 영향(데스크톱 Node 측정, 폰은 3~5배): players 컴파일+실행 40ms, tfh 10ms, hgTM 9ms. **시작 지연의 주원인은 데이터 파싱이 아니라 ①의 buildSQ 반복**. 다만 폰 메모리(JS 힙)에는 큰 객체가 전부 상주
- 줄이는 방법(효과 큰 순)
  * 지연 파싱: tfh·mig29x·tm308·add307을 `<script type="application/json" id="...">`로 넣고 처음 필요할 때 `JSON.parse` → 시작 파싱 0, 힙 상주 없음(파일 크기는 그대로)
  * tfh 압축 표기: 날짜 → 2000-01-01 기준 일수(정수), 방식 'T/F/L' → 0/1/2, 이적료 → 만 유로 단위, 선수별 배열을 열(column) 배열 1개로 → 추정 1.9MB → 0.8~0.9MB
  * tfh 대상 축소: 게임에 있는 선수 중 최근 8건만(현재 평균 4.1건이라 효과 작음), 구단명 9,136개 중 게임 밖 구단은 그대로 필요
  * hgTM: 이미 21세가 지난 선수는 결과(c/a/없음 + 구단)만 저장, 21세 미만만 일수 이력 유지 → 0.52MB → 약 0.1MB 예상
  * ENGINE_SRC 중복 제거: 엔진을 `<script type="text/plain" id="eng">` 한 번만 넣고 화면용은 `new Function`/script 삽입, 워커는 같은 텍스트로 Blob 생성 → 약 0.28MB 감소
  * 3D 자산: base64를 처음 3D 리플레이를 열 때만 디코드(이미 그렇다면 유지). 앱(android) 빌드는 assets 폴더 파일로 분리해 base64 33% 팽창 제거 → 약 0.8MB 감소
  * players.json: 사진 파일명 `"<id>-<숫자>.jpg"`의 id 중복 제거, 소수(성향 3개 등) 정수화 → 5~10% 예상
- 목표치 제안: 개인용 HTML 12.7MB → 약 10MB, 시작 파싱 대상 약 7MB

## 4. 26개 리그 규정 일괄 구현 — 데이터 구조 제안
### 현재 흩어진 규정 상수
- SQR(외국인 m/h), SQMAX·OWNMAX·RES_REG(1군 30·보유 40), RES_AGE(23), BAN_R(경고 누적), HG_RULE(홈그로운 문구), NT_EU_LG(비EU 표시), 벤치 9명(teamFor의 slice(0,9))
### 제안: 리그 규정 표 하나(LGRULE) + 판정 함수 하나
```js
const LGRULE={
 _def:{reg:30,own:40,resAge:23,bench:9,card:{every:5}},
 ES:{reg:25,uExempt:{age:23,need:'res'},nonEU:{h:3},card:{every:5},st:{reg:'✓',nonEU:'✓'}},
 EN:{reg:25,uExempt:{age:21},hg:{club:0,assoc:8,win:[15,21],days:1065},card:{en:1,dom:1},st:{...}},
 IT:{reg:25,uExempt:{age:22},hg:{club:4,assoc:8},...},
 TR:{foreign:{h:14,born:{n:4,from:'2003-01-01'}}},
 SA:{foreign:{h:10,born:{n:2,from:'2004-01-01'},m:8}},
 FR2:{inh:'FR',bench:7}, ...
};
```
- 원칙
  * 키 = 리그 코드, `inh`로 2부가 1부를 상속(EN2 → EN), 없는 값은 `_def`
  * 항목마다 `st`(✓ 확정 / △ 추정)와 `src`(ops/05 근거 행) → 화면 '추정' 표시를 같은 표에서 생성
  * `from`(적용 시작일): 기존 세이브는 `S.ruleFrom`(다음 이적시장 시작일) 전에는 v309 규정 사용 → "기존 세이브는 다음 이적시장부터" 결정을 코드 한 줄로
  * 규정 표는 `src/data/LGRULE.json`으로 분리 → 조사 문서(ops/05)와 표를 스크립트로 대조 가능
- 판정 함수(모든 경로가 이것만 사용)
  * `regCheck(c)` → {등록 인원, 예외 인원, 외국인/비EU, 홈그로운 부족, 위반 목록}
  * `eligible(p,c,ctx)` → 경기 출전 가능 여부와 이유(②④ 해결)
  * `canSign(p,c)` → 영입 관문(사용자: 이유 표시 / AI: 판정만)
  * `fixSquad(c)` → AI 자동 정리(2군 내림 → 임대 → 해지 순)
  * 기존 SQR·BAN_R·RES_REG 등은 LGRULE에서 읽는 얇은 호환 함수로 남기고 점진 교체
- 홈그로운 규정(EPL 8, 세리에A 8+4 등)은 "등록 25명 중 HG 부족분만큼 등록 인원 감소" 방식이 실제 규정과 같고 구현이 단순(EPL: 비HG 최대 17명)
