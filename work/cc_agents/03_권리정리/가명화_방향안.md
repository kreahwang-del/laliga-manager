## □ 3. 구단명 ★ 핵심 선택
| 안 | 예 | 권리 위험 | 몰입감 | 같은 도시 라이벌 |
|---|---|---|---|---|
| A. 실제 도시 + 가상 접미사 | "마드리드 아틀란티스" / "마드리드 메리디안" (예시일 뿐, 실제 구단명 검사 전) | 낮음~중간 (도시명은 자유, 조합이 실제 구단과 같거나 비슷하면 위험) | 높음 | 같은 도시 2팀에 서로 다른 접미사 → 더비 유지 쉬움 |
| B. 실제 지역·자연 지명(강·산·광역) + 가상 이름 | "만사나레스 유나이티드"(실제 하천명) | 낮음 (실제 구단 연고 이름이 들어가는 경우만 주의) | 중간 | 같은 도시 안 다른 지명 → 라이벌 유지 가능 |
| C. 완전 가상 도시 | "노르바 시티", "칼데라 FC" | 매우 낮음 | 낮음 (지도·국가 사다리와 연결이 약해짐) | 가상 도시 하나에 2팀 배정 |
| D. 혼합(추천) | 대도시·유명 연고지는 B, 나머지는 A | 낮음 | 중간~높음 | 라이벌 표(`DERBY`·`DERBY_N`)를 새 이름 쌍으로 변환 |

  - 위험 판단은 변호사 확인 권장(도시 + 전력 서열 유지가 "연상"으로 문제될 수 있는지)

## □ 4. 선수명 ★ 생성 방식
- ㅇ 방식: 국적별 이름표(`NAMES`) → 이름 × 성 무작위 조합(시드 고정)
- ㅇ 현재 `NAMES`: 17개국(KOR·JPN·USA·SCO·SUI·AUT·NED·TUR·DEN·ESP·ENG·ITA·GER·FRA·BRA·ARG·POR), 조합 4,796개
  - 선수 국적 코드 173종 중 이 17개국이 덮는 선수는 5,642/12,042명(47%) → 최소 40개국 이상으로 확장 필요(벨기에·멕시코·사우디·중국·콜롬비아·우루과이·세네갈·노르웨이 등)
  - 국적 코드 정규화 먼저(ESP/SPA, JPN/JAP, NED/HOL/NET, SUI/SWI, TUR/TÜR)
- ㅇ 실명 충돌 실측: 지금 이름표 조합 4,796개 중 230개(4.8%)가 게임 안 실제 선수 이름과 정확히 같음 (예: "Min-jun Kim", "Kaito Suzuki", ESP 100건)
  - → 흔한 이름끼리 조합하면 실존 선수와 우연히 같아지는 일이 많음. 충돌 방지 규칙 필수
- ㅇ 충돌 방지 규칙(추천)
  1. 원본 실명 11,917개 + 감독 59명과 정규화(악센트·대소문자·하이픈 제거) 후 같으면 탈락
  2. 성 + 이름 첫 글자가 같고 국적이 같으면 탈락 (예: "K. Mbappé" 형태 연상 방지)
  3. 시장가치 상위 500명(원본 기준)의 성은 같은 국적에서 쓰지 않음 (흔한 성 García·Silva 등은 예외 목록으로 관리)
  4. 한 단어 이름(Pedri·Koke 같은 별명형)은 생성하지 않거나, 가상 별명 목록에서만 뽑음
  5. 게임 안 이름 중복은 같은 리그 안 금지
  - 검사용 원본 목록은 빌드 단계에서만 쓰고 배포 파일에 넣지 않음
- ㅇ 대안(★): 이름표를 사람이 만든 목록 대신 "음절 조합기"로 만들면 충돌이 거의 없지만 국적 느낌이 약해짐 → 추천은 이름표 확장 + 규칙 1~5

## □ 6. 구단 색·엠블럼 (ux-design 담당, data-rights는 금지 목록 제공)
- ㅇ 색 생성 규칙(제안)
  - 기본색·보조색·패턴(단색·세로 줄무늬·가로 줄무늬·띠)을 새로 뽑음
  - 금지: 같은 나라 실제 구단의 (기본색, 보조색, 패턴) 조합과 색 거리 ΔE < 15 이내 → 금지 목록은 `COLORS` 9 + `KITS3D` 450에서 빌드 때만 생성
  - 유명 패턴 금지 목록: 자주·남색 세로 줄무늬, 흑백 세로 줄무늬, 녹백 가로 띠, 흑청 세로 줄무늬 등(수동 20~30개)
  - 같은 리그 안 색 겹침 최소화(경기 화면 구분용, 기존 원정색 교체 로직 재사용)
- ㅇ 엠블럼: 절차 생성(방패·원·다이아몬드 틀 + 이니셜 + 단순 도형 + 구단 색)
  - 금지: 실제 구단의 상징물 조합(왕관+이니셜, 박쥐, 수탉, 독수리+구단색 등) → 도형 목록에서 동물·왕관은 빼거나 형태를 일반화
  - 외부 이미지 사용 안 함(전부 코드로 그림)
- ㅇ 유럽대항전·리그 로고도 같은 방식으로 새로 만듦

## □ 8. 수치 재생성(분포 유지)
- ㅇ 선수 ★
  - 추천(재표본): 리그 × 구단 등급(서열 4~5구간) × 포지션 × 나이대별로 OVR·PA·세부 능력치·키·주발·시장가치·연봉·계약 분포(평균·분위수·상관)를 만들고, 각 가상 구단의 선수단을 이 분포에서 새로 뽑음
    - 구단별 선수 수·포지션 구성·평균 나이·상위 16명 평균 능력치는 원래 구단과 비슷하게 맞춤(사실성)
    - 개별 선수와 원본의 1:1 대응 없음
  - 대안(노이즈): 원본 선수마다 능력치 ±N 흔들기 → 사실성은 가장 높지만 EA FC·TM 값의 파생물이 그대로 남음 → 비추천
- ㅇ 선수 유형·특성(`pst`, FC26 플레이스타일 기반)·성향(`tend` 등): 포지션·유형별 빈도 분포에서 다시 뽑음
- ㅇ 외모(`LOOK3D`, TM 사진에서 추출): 폐기. 피부·머리색·머리 모양은 무작위 생성(국적별 가중치를 둘지는 ux-design과 협의 — 고정관념 논란 주의)
- ㅇ 유니폼(`KITS3D`): §6 새 색으로 대체
- ㅇ 구단 재정: 매출·예산·연봉 상한을 리그 × 서열별 분포로 다시 만듦. `revSrc` 표기 삭제(또는 "게임 설정"), Deloitte 분기(`/딜로이트/`)는 상위 구단 플래그로 대체
- ㅇ 경기장 수용 인원(`STAD`): 리그 × 서열 분포에서 생성
- ㅇ `TOCAL`(실명 키 보정 160명): 삭제하거나 유형별 값으로 일반화
- ㅇ 리그 단위 기준값(경기당 골·홈 이점·이적 지출 등 §5 기준값)은 유지 → 사실성의 핵심, 공개 통계 평균이라 위험 낮음

## □ 10. 유저 편집 기능(유저가 직접 실명 입력) ★ 허용 여부 — 장단점만
| 구분 | 장점 | 단점·위험 |
|---|---|---|
| 허용 안 함 | 권리 위험 가장 낮음, 스토어 심사 단순 | 실명을 원하는 마니아층 만족도 낮음 |
| 내 구단·감독 이름만 편집 | 몰입감 일부 확보, 위험 낮음 | 다른 구단·선수는 그대로 |
| 전체 이름 편집(기기 안에서만, 공유 없음) | 마니아 만족도 높음 | 구글 플레이 "침해를 조장·유도하는 앱" 조항 해석 여지. 스토어 문구·튜토리얼에서 실명 입력을 권하면 위험 커짐 |
| 편집 + 파일 불러오기·공유 | 커뮤니티 활성화(PES 옵션 파일, FM 실명 패치 방식) | 실명 데이터 파일 유통의 통로가 됨 → 위험 가장 큼. 맨유 v. SEGA 보도에서 "모드 지원"이 쟁점으로 언급됨 |
- ㅇ 참고: FM·PES 모두 개발사는 실명 파일을 직접 배포하지 않고 팬이 만든 것을 방치하는 구조
- ㅇ 결정 시점: 출시 1차는 "내 구단·감독 이름만"으로 두고, 확장은 출시 후 판단하는 방법도 있음(변호사 확인 권장)
